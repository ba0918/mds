## Agreements

仕様の成立時（2026-09-16）に決めたもの: A1〜A7、A14〜A20、P1、R1〜R5。
実装サイクルで裁定したもの（2026-09-17）: A8〜A11。
項目の中の表の検査のために決めたもの（2026-09-21）: A12、A13。

- A1 mds は、文書の frontmatter の "$schema" が指す YAML のスキーマで Markdown の文書を検査し、値を抽出する CLI にする。LLM が書いた Markdown の書式を機械的に固定できるようにするのが目的
- A2 検査の既定は閉じた世界にする。スキーマに宣言していない見出しと行を誤りにする。緩めるのはスキーマの "open" と CLI の "--open" の2つで、緩める方向にしか働かない
- A3 スキーマは YAML で書く。型付きで読めるため
- A4 抽出した値の型は全部文字列にする。型変換はしない
- A5 見出しの深さは3段（題名、節、項目）までにする。再帰的な任意深さの入れ子は持たない
- A6 文書をまたぐ整合性検査（ID の一意性、参照解決、用語集の連鎖、出典の解決）は持たない。責務が大きくなるため、kotowari の領分として残す
- A7 設定ファイルは設けない。設定は CLI のフラグとスキーマの中のフラグで足りる
- A8 frontmatter が YAML のマッピングでないときは検査を行わずに停止する。"$schema" の値が空か空白だけのときも同じ
- A9 開いた世界では、題名より前の見出しを未宣言の構造として許す。閉じた世界では誤りにする
- A10 一覧のマーカー "-"、"*"、"+" は同じ扱いにする。スキーマが宣言した名前と一致すればフィールド行、一致しなければ箇条書きとして読む
- A11 箇条書きの抽出の要素は、再構成せず元の行をそのまま保つ。行頭の空白とマーカーの後の空白も含める
- A12 項目にも表とコードブロックを宣言できるようにする。規則の中身、既定の出現回数、誤りの種類は節に宣言したときと同じにする。見出しの下に表を持つ決定表のような項目を検査できるようにするため
- A13 表の "header" は省略できるようにする。省略したときはヘッダと列数を検査せず、表の有無と出現回数だけを検査する。表ごとにヘッダの違う表を宣言できるようにするため。コードブロックの "lang" が省略できるのと同じ扱いにそろえる
- A14 スキーマの指定は、文書からの相対パスと URL の2つを受ける。URL のスキーマは取得した内容を SHA-256 の名前でキャッシュし、壊れたキャッシュは再取得して回復する
- A15 終了コードは、指摘が無いときが 0、指摘があるときが 1、検査を行えなかったときが 2 の3値にする
- A16 出力の形は "--format" で text と json から選ぶ。text は人間向けの1行1件、json は機械向け
- A17 指摘は、種類、深刻度、文書のパス、行番号、詳細の5つを持つ形にする。行を持たない指摘では行番号を省く
- A18 スキーマ言語、検査、抽出のコアは CLI のフレームワークに依存しない別のクレートに置く。kotowari の中から再利用できるようにするため
- A19 検査と別に、Markdown の素の構文木を mdast に沿った JSON で出す手段を持つ。位置情報は出力に含めない
- A20 スキーマの推奨の置き場は ".mds/schemas/"、URL のスキーマのキャッシュの置き場は ".mds/cache/" にする

## Prohibitions

- P1 読めない、壊れている、形に合わない入力を黙って飛ばさない。スキーマを解決できないときと frontmatter が壊れているときは、部分的な結果を出さずに停止する

## Rejected

- R1 スキーマを Markdown のルール行で書く（なぜ: 機械検査できる形に落とすと独自の DSL になる。YAML のほうが型付きで読める。A3）
- R2 文書をまたぐ整合性検査を mds に含める（なぜ: 責務が大きくなる。kotowari の領分。A6）
- R3 抽出した値を日付や数値へ型変換する（なぜ: 利用者の解釈を固定する。文字列が共通分母。A4）
- R4 表の中身を抽出しない（なぜ: 用語集や決定表の中身を値として取れるほうが便利。A4）
- R5 設定ファイル ".mds/config.yaml" を設ける（なぜ: CLI のフラグとスキーマの中のフラグで足りる。A7）

## Undecided

- U1 抽出値の型付け。要求する実利用者が現れたら、スキーマに任意の "type" を足す
- U2 項目の抽出を、配置パスをキーにしたオブジェクトにするかどうか。文書をまたぐ検査に項目の構造化された値が要るようになったら決める
- U3 抽出した値に行番号を添えるかどうか。U2 と同じ場面で決める
